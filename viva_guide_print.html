PART A: PROJECT OVERVIEW

1. What GreenWardrobe Does

GreenWardrobe is an intelligent, user-friendly sustainable fashion web application. It enables consumers to upload a photograph or capture a live camera shot of any clothing item or care label. The system analyzes the textile fiber composition (such as Organic Cotton, Linen, Polyester, or Elastane) and calculates its environmental Life Cycle Assessment (LCA) impact—quantifying:

  • Sustainability Eco-Score (0 to 100) with letter tiers (A+ to D).
  • Water Consumption (liters required during agriculture and textile dyeing).
  • Carbon Footprint (kg of $\text{CO}_2\text{e}$ emitted across manufacturing).
  • Energy Requirements (kWh consumed).
  • Microplastic Risk & Biodegradability Status.
  • Actionable Circular Recommendation: Categorized into 5 decisions: BUY, THINK TWICE, REPAIR, REUSE, or SECOND-HAND.

2. Problem Statement

The fashion industry is responsible for:

  • 10% of global carbon emissions (more than international flights and maritime shipping combined).
  • 20% of global industrial wastewater from toxic fabric dyeing and treatment.
  • Over 500,000 tons of synthetic microfibers dumped into oceans annually via laundry wash cycles (equivalent to 50 billion plastic bottles).
  • Consumers lack transparent, accessible information when shopping or sorting their wardrobes, leading to impulse purchases of high-emission, non-biodegradable synthetic garments that end up in landfills within 12 months.

3. Project Objectives

  1. Provide an intuitive, responsive interface for uploading garment photos or using a device webcam/phone camera.
  2. Present complex Life Cycle Assessment (LCA) environmental metrics through clear, easy-to-understand visual progress bars, metrics cards, and benchmark comparisons.
  3. Guide user behavior using the 5-Tier Circular Economy Model (Buy, Think Twice, Repair, Reuse, Second-Hand).
  4. Establish a clean, decoupled frontend-backend architecture connected via RESTful API standards with built-in educational Demo Fallback.

PART C: REST API MASTERCLASS FOR BEGINNERS

Read this section thoroughly before your viva! This gives you complete mastery over REST APIs.

1. What is an API?

API stands for Application Programming Interface. Think of an API as a waiter in a restaurant:

  • You are the customer (Client).
  • The kitchen is the database / server (Backend).
  • You cannot walk into the kitchen yourself. Instead, you tell the waiter your order. The waiter delivers your order to the kitchen and brings back your food.
  • The waiter is the API. It is a standardized messenger that allows two software programs to communicate.

2. What is a REST API?

REST stands for Representational State Transfer. A REST API is an architectural style for network communication that follows standard web conventions:

  1. Stateless: The server does not store session memory of past requests. Every request must contain all information required to understand and process it.
  2. Client-Server Separation: The user interface (React frontend) is completely decoupled from data storage and business logic (Python/Node backend). They can be hosted on different servers and updated independently.
  3. Standard HTTP Methods: Communicates using standard HTTP verbs (GET, POST, PUT, DELETE).
  4. Data Format: Exchanging data predominantly using lightweight JSON (JavaScript Object Notation).

3. Why Does GreenWardrobe Need a REST API?

In our project:

  • React Frontend: Runs inside the user's web browser. It handles image upload, UI layout, animations, and renders buttons. However, a browser cannot run heavy deep-learning computer vision models (such as PyTorch, YOLO, or ResNet) without freezing the user's computer.
  • Backend Server: Runs on a powerful cloud server or Python environment. It hosts the AI models that inspect garment images, recognize care tags, and query Life Cycle Assessment databases.
  • REST API: Bridges the two. React sends the image to the backend via POST /api/analyze-clothing, the backend analyzes it, and sends back a JSON response.

4. Client vs. Server

Concept What It Is In GreenWardrobe
Client The user-facing program that initiates requests. Our React application running in the user's Chrome/Firefox browser.
Server The computer/program listening for requests, executing calculations, and storing data. The Python (Flask/FastAPI) or Node.js server listening on http://localhost:5000.

5. HTTP Methods (Verbs)

HTTP Method Purpose GreenWardrobe Example
GET Retrieve data from server (read-only; no side effects). GET /api/clothing-results/scan-101 (fetch previous analysis).
POST Submit new data to server (creates or processes). POST /api/analyze-clothing (send clothing image for AI analysis).
PUT Replace or update existing data entirely. PUT /api/user-profile (update user's sustainable wardrobe goals).
DELETE Remove data from server. DELETE /api/saved-garment/scan-101 (delete a scan from history).

6. What is an API Endpoint?

An endpoint is a specific URL path on a server where a particular service can be accessed.

  • Example: http://localhost:5000/api/analyze-clothing
    • Protocol: http://
    • Host/Domain: localhost
    • Port: :5000
    • Route / Path: /api/analyze-clothing

7. What is JSON?

JSON stands for JavaScript Object Notation. It is the standard text-based format for sending structured data across the internet.

{
  "name": "Organic Cotton T-Shirt",
  "score": 88,
  "isSustainable": true,
  "materials": ["Organic Cotton", "Elastane"]
}
  • In JavaScript, we convert a JSON string to a JS object using response.json() or JSON.parse().
  • We convert a JS object to a JSON string using JSON.stringify(object).

8. What are HTTP Status Codes?

HTTP status codes are 3-digit numbers returned by the server indicating the outcome of a request:

  • 2xx = Success:
    • 200 OK: Request succeeded.
    • 201 Created: New resource was successfully created.
  • 4xx = Client Error:
    • 400 Bad Request: Invalid input (e.g. uploaded file was not an image).
    • 404 Not Found: The requested endpoint or garment ID does not exist.
    • 413 Payload Too Large: The image file exceeds the server's upload size limit.
  • 5xx = Server Error:
    • 500 Internal Server Error: Backend crashed or threw an unhandled exception.
    • 503 Service Unavailable: Server is overloaded or down for maintenance.

9. What is fetch()?

fetch() is a built-in modern JavaScript function used to make asynchronous network requests without needing external libraries like Axios.

  • It returns a Promise that resolves to the Response object.
  • Syntax:
    fetch(url, options)
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error(error));

10. What is async and await?

async/await is modern ES6+ syntactic sugar built on top of JavaScript Promises. It allows us to write asynchronous code that reads like synchronous step-by-step code:

  • An async function always returns a Promise.
  • The await keyword pauses execution inside the async function until the Promise resolves or rejects.
async function getResults() {
  const response = await fetch("http://localhost:5000/api/data"); // Wait for network
  const data = await response.json(); // Wait for JSON parsing
  return data;
}

11. What is FormData?

When we send regular text or numbers, we send JSON with 'Content-Type': 'application/json'. However, raw binary files (such as JPEG, PNG, or video) cannot be easily placed into a standard JSON string. Instead, web standards use FormData:

const formData = new FormData();
formData.append("image", imageFile); // Appends the binary file

The browser automatically encodes this using multipart/form-data with unique boundary delimiters.

Crucial Rule: When passing FormData into fetch(url, { method: 'POST', body: formData }), NEVER manually set 'Content-Type': 'multipart/form-data'. If you set it manually, you will overwrite the boundary string generated by the browser, causing the server to fail to parse the upload!

12. What is CORS?

CORS stands for Cross-Origin Resource Sharing. It is a browser security mechanism.

  • If your React frontend runs on http://localhost:5173 and tries to call a backend on http://localhost:5000, they have different ports (different origins).
  • By default, the browser blocks this request unless the backend server sends specific HTTP response headers:
    Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, POST, OPTIONS
  • In a Python Flask backend, CORS is enabled using from flask_cors import CORS; CORS(app).

Category 1: General Project Questions

Q1. What is GreenWardrobe?

Answer: GreenWardrobe is a sustainable fashion web application built with React. It analyzes the environmental impact of clothing by evaluating fabric composition, calculating water consumption, carbon footprint, and energy usage, and offering 5 circular fashion recommendations.

Q2. Why did you choose sustainable fashion as your project domain?

Answer: The fashion industry generates 10% of global greenhouse gases and 20% of global industrial wastewater. Consumers often lack information about the ecological toll of synthetic fabrics like polyester. GreenWardrobe bridges this gap with transparent, data-driven environmental scores.

Q3. What was your specific responsibility in this project?

Answer: I was responsible for the entire frontend engineering and UI/UX design: building the component architecture, image upload with validation, live device camera capture, state management, REST API integration using the Fetch API, and responsive styling with Tailwind CSS.

  1. BUY: For certified eco-friendly, low-impact staples.
  2. THINK TWICE: For synthetic blends or impulse items with high carbon/water tolls.
  3. REPAIR: To mend or patch durable garments, extending their lifespan.
  4. REUSE: To upcycle worn textiles into functional goods like tote bags or rags.
  5. SECOND-HAND: To buy thrifted or donate clothes, avoiding virgin textile production.

However, for this college presentation, the application includes a Demo Mode with realistic sample data based on published textile Life Cycle Assessment literature, ensuring reliable demonstration even when an external server is offline.

Category 2: React.js Architecture & Hooks

Q7. What is React.js?

Answer: React is an open-source JavaScript library developed by Meta for building user interfaces. It uses a component-based architecture and a virtual DOM to efficiently update and render UI elements when data changes.

Q8. Why did you use Vite instead of Create React App (CRA)?

Answer: Create React App is deprecated and relies on Webpack, which bundles the entire application before starting, resulting in slow startup times. Vite uses native browser ES modules during development, delivering instant server start and lightning-fast Hot Module Replacement (HMR).

Q9. What is JSX?

Answer: JSX stands for JavaScript XML. It is a syntax extension for JavaScript that allows us to write HTML-like markup directly within JavaScript files. It is transpiled into standard React.createElement() calls by build tools.

Q10. What is a React component?

Answer: A component is a self-contained, reusable block of code that outputs UI. In modern React, components are written as JavaScript functions that take props as input and return JSX markup.

Q11. What is the useState hook and how did you use it?

Answer: useState is a React hook that allows functional components to manage local state. In App.jsx, I used it to store activeTab, selectedImage, analysisResult, and isLoading. Whenever setState is called, React re-renders the component with the new data.

Q12. What is the useEffect hook and why did you use it?

Answer: useEffect allows components to perform side effects (such as data fetching, timers, or subscribing to browser APIs) after rendering. In App.jsx, I used useEffect with an empty dependency array [] to run a backend health check once when the component mounts.

Q13. What is the difference between props and state?

Answer:

  • State: Internal data owned and managed within a component that can change over time via its updater function.
  • Props: External data passed from a parent component down to a child component. Props are read-only (immutable) for the child.

Category 3: Modern JavaScript (ES6+)

Q14. What are Promises in JavaScript?

Answer: A Promise is an object representing the eventual completion or failure of an asynchronous operation. A Promise exists in one of three states: pending, fulfilled, or rejected.

Q15. Why do we prefer async/await over chaining .then()?

Answer: async/await makes asynchronous code look and behave like synchronous code. It eliminates "callback hell" and deeply nested .then() chains, making error handling cleaner with standard try...catch blocks.

Q16. What is object destructuring?

Answer: Destructuring is an ES6 feature that extracts properties from objects into distinct variables. For example: const { score, grade } = impactData; extracts score and grade directly.

Q17. What is the difference between let, const, and var?

Answer: var is function-scoped and hoisted, which often causes bugs. let and const are block-scoped. const is for variables that will not be reassigned, while let is for variables whose values will change.

Q18. What is an arrow function?

Answer: Arrow functions provide a concise syntax for writing function expressions (() => { ... }) and lexically bind the this value from their enclosing scope.

Q19. What does URL.createObjectURL() do?

Answer: It creates a temporary DOMString containing a URL representing the specified file object. In our app, it allows us to preview user-selected images in the browser instantly without uploading them to a remote server.

Category 4: HTML5 & Tailwind CSS

Q20. What is Tailwind CSS?

Answer: Tailwind CSS is a utility-first CSS framework. Instead of writing custom CSS rules in separate stylesheet files, we apply pre-defined utility classes directly to HTML elements (e.g. bg-emerald-600 text-white p-4 rounded-xl).

Q21. What are the advantages of Tailwind CSS over standard CSS?

Answer:

  1. Faster development: No need to invent arbitrary class names or jump between CSS and JS files.
  2. Design consistency: Enforces consistent spacing, color palettes, and typography.
  3. Small production bundle: Tailwind purges unused CSS classes during the build step.

Q22. How did you achieve responsive design?

Answer: Tailwind uses mobile-first responsive breakpoints:

  • Default: Mobile layout
  • sm: (min-width: 640px)
  • md: (min-width: 768px)
  • lg: (min-width: 1024px) For example, grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 displays 1 column on mobile, 2 columns on tablets, and 3 columns on desktops.

Q23. Why did you choose a green and neutral color scheme?

Answer: The color palette (emerald green, teal, and slate neutrals) visually reinforces the project's sustainability and eco-friendly theme, creating an accessible, professional aesthetic.

Q24. What semantic HTML elements did you use?

Answer: <header>, <nav>, <main>, <section>, <footer>, <button>, and <input>. Semantic tags improve code readability, accessibility for screen readers, and SEO.

Category 5: Image Upload & Camera Questions

Q25. How does the image upload feature work in your code?

Answer: We use an HTML <input type="file" accept="image/*">. When the user selects a file, the onChange event fires. Our handler validates the file's MIME type and size, generates a preview URL using URL.createObjectURL(), and updates React state.

Q26. What validations did you implement for image uploads?

Answer:

  1. Type Validation: Must match ['image/jpeg', 'image/png', 'image/webp'].
  2. Size Validation: Cannot exceed $5\text{ MB}$ ($5 \times 1024 \times 1024\text{ bytes}$). If a file fails, an error message is displayed and the upload is rejected.

Q27. How does drag-and-drop file upload work?

Answer: We attach HTML5 drag-and-drop event listeners (onDragOver, onDragLeave, onDrop) to a container div. In onDrop, we call e.preventDefault() to stop the browser from opening the file as a new tab, and extract the file from e.dataTransfer.files[0].

Q28. How does camera capture work without an external library?

Answer:

  1. We call navigator.mediaDevices.getUserMedia({ video: true }) to access the device webcam.
  2. The live video stream is piped to an HTML5 <video> element.
  3. When the user clicks "Snap Photo", we draw the current video frame onto an invisible <canvas> using ctx.drawImage().
  4. We convert the canvas to a JPEG Blob using canvas.toBlob() and wrap it into a standard File object.

Q29. Why must you stop media stream tracks when closing the camera?

Answer: If we don't call track.stop() on all video tracks, the device camera hardware remains active, draining battery and keeping the laptop's green camera indicator light on, which is a major privacy and resource issue.

Category 6: REST API & Backend Integration

Q30. What is a REST API endpoint?

Answer: An endpoint is a specific URL where a client application sends requests to interact with server resources (e.g. POST http://localhost:5000/api/analyze-clothing).

Q31. Why did you use FormData instead of sending JSON for image upload?

Answer: JSON is a text format. Images are binary data. FormData formats data as multipart/form-data, which transmits raw binary files efficiently alongside text fields without requiring expensive Base64 encoding.

Q32. Why do you not set the Content-Type header when sending FormData in fetch?

Answer: When FormData is passed to fetch(), the browser automatically sets the Content-Type header to multipart/form-data and generates a unique boundary string (e.g. boundary=----WebKitFormBoundary...). If we set it manually, the boundary is omitted, and the backend cannot parse the incoming file parts.

Q33. What does response.json() do?

Answer: It reads the incoming HTTP response body stream to completion and returns a Promise that resolves to the parsed JavaScript object representation of the JSON data.

Q34. How does your frontend handle backend connection failures?

Answer: The fetch call is wrapped in a try...catch block. If the server is offline or returns an error, the catch block catches the network failure and activates the graceful fallback, returning simulated data and alerting the user that Demo Mode is active.

Q35. What is CORS and how does it affect your application?

Answer: CORS (Cross-Origin Resource Sharing) is a browser security policy preventing web pages from making requests to a different domain/port than the one serving the web page. To allow React on port 5173 to call an API on port 5000, the backend must return headers like Access-Control-Allow-Origin: *.

Category 7: Environmental Life Cycle Assessment (LCA)

Q36. What is a Life Cycle Assessment (LCA)?

Answer: LCA is a scientific methodology used to evaluate the environmental impacts of a product throughout its entire life cycle—from raw material extraction ("cradle") through production, usage, and disposal or recycling ("grave").

Q37. Why is conventional cotton considered water-intensive?

Answer: Producing just one standard conventional cotton t-shirt requires approximately 2,700 liters of water—enough drinking water for one person for 2.5 years. Organic cotton, by contrast, relies largely on rainwater and avoids toxic pesticides.

Q38. What is the environmental concern with polyester garments?

Answer: Polyester is a synthetic fiber derived from petroleum (fossil fuels). Its production is energy- and carbon-intensive, it does not biodegrade in landfills (persisting for 200+ years), and it sheds microplastics into water systems during laundering.

Q39. What is the "30 Wears" rule in sustainable fashion?

Answer: It is a consumer awareness campaign encouraging shoppers to ask: "Will I wear this garment at least 30 times before discarding it?" Extending a garment's life by just 9 months reduces its carbon, water, and waste footprints by 20–30%.

Q40. Are the environmental figures in your project real scientific measurements?

Answer: No. They are realistic educational estimates modeled from published Life Cycle Assessment (LCA) textile literature for academic demonstration. The frontend clearly displays an educational disclaimer.

Category 8: Code-Specific Implementation Questions

Q41. Where is the API base URL configured in your project?

Answer: In src/services/api.js on line 27: export const API_BASE_URL = "http://localhost:5000/api";

Q42. How does conditional rendering work in your App.jsx?

Answer: We use JavaScript logical AND (&&) and ternary operators. For example: {analysisResult && <EnvironmentalImpact impactData={analysisResult.environmentalImpact} />} This ensures the environmental dashboard only renders once an analysis result is present.

Q43. How do you prevent memory leaks when creating preview URLs?

Answer: Whenever the user removes or replaces an image, we call URL.revokeObjectURL(imagePreviewUrl) to release the allocated memory in the browser.

Q44. How does the user switch between Demo Mode and Live API Mode?

Answer: Through the mode toggle button in Navbar.jsx. It toggles the useDemoMode boolean state in App.jsx, which is then passed to analyzeClothingImage(selectedImage, useDemoMode).

Q45. Why is the key prop required when rendering lists in React?

Answer: The key prop gives React elements a stable identity across renders. It helps the Virtual DOM algorithm identify which items were added, changed, or removed, avoiding unnecessary re-renders of the entire list.
